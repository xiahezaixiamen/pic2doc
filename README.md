# 图片转文档

**线上地址：https://xiahezaixiamen.github.io/pic2doc/**

手机端小工具：把多张图片、或者已有的 PDF，按你排好的顺序导出成新的 PDF 或 Word。
所有处理都在浏览器本地完成，文件不会上传到任何服务器。

可以拿它做：图片转 PDF / Word、把长文档拆页后只保留需要的几页、调整页序、合并多张图与 PDF 页面。

## 怎么用

1. 点「添加」，可选图片（可多选、可拍照）或 PDF 文件
2. 多页 PDF 会自动拆成单页，每页变成一张卡片
3. 用每张卡片下方的 ↑ ↓ 调整顺序，左上角数字就是新文档的页序
4. 不需要的页点右上角 × 删掉（比如 5 页只留 3 页）
5. 列表顶部显示当前占用大小；点「清理全部」可一次性释放（需再点一次确认，防误触）
6. 需要的话关掉「Word 每张图片单独一页」，改成连续排版
7. 点「导出 PDF」或「导出 Word」，得到重新生成的文件

### 导出后文件去哪了

- **手机上**：不自动下载。生成后直接弹出系统分享面板，可以发微信、发邮件、存到「文件」App。如果只是想发出去，**关掉面板就什么都不会留下**，不占手机空间。
- **在微信里打开**：微信会接管分享接口，弹出来的是微信转发面板而不是系统面板，存不了文件，所以在微信内一律改为直接下载，并在页面顶部提示「建议在浏览器中打开」。iOS 微信内置浏览器不支持文件下载，点了可能没有反应，需要点右上角「…」→「在浏览器中打开」。
- **电脑上**：按常规下载到下载目录。

这样处理的原因是：下载会永久占用本地存储，而且要在下载目录里手动清理；手机上多数时候只是想发给别人，没必要先落一份盘。

## 怎么打开

必须通过 http 访问，不能直接双击 index.html（浏览器对本地文件的脚本有限制）。

在本目录下起个静态服务即可：

```
python -m http.server 8080
```

然后浏览器打开 `http://127.0.0.1:8080/`。

手机上测试时，让手机和电脑在同一 Wi-Fi 下，用电脑的局域网 IP 访问（例如 `http://192.168.1.10:8080/`）。

## 部署

整个目录就是纯静态站点，已部署在 GitHub Pages（仓库 [xiahezaixiamen/pic2doc](https://github.com/xiahezaixiamen/pic2doc)，`main` 分支根目录）。

更新流程：

```
git add -A && git commit -m "说明" && git push
```

推送后 GitHub Pages 会自动重新构建，约 1 分钟后生效。

也可以丢到任意其他静态托管（Cloudflare Pages、Vercel、对象存储等），无需后端。
支持加到手机主屏幕（PWA），离线也能用。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面结构 |
| `style.css` | 样式（手机优先） |
| `app.js` | 全部逻辑：读图、排序、压缩、导出 |
| `lib/jspdf.umd.min.js` | 生成 PDF |
| `lib/docx.iife.js` | 生成 Word |
| `lib/pdf.min.js` / `lib/pdf.worker.min.js` | 读取已有 PDF、逐页渲染 |
| `manifest.webmanifest` / `sw.js` / `icon-*.png` | PWA 安装与离线 |

## 实现细节

- 图片读取用 `createImageBitmap`，会自动按 EXIF 旋转，避免手机竖拍照片导入后方向错乱
- 已有 PDF 用 pdf.js 逐页渲染成图片（最长边 2000px），再走统一流程，所以删页、调序、混合图片都能用
- 大图先压到长边 2000px、JPEG 质量 0.88，控制导出体积
- PDF 按 A4 竖版、每张图一页、等比缩放居中
- Word 按 A4、图片等比缩放到页面可用宽度内，可选每张一页或连续排版

## 已知限制

- iPhone 的 HEIC 格式，部分浏览器无法解码，会提示读取失败。可先在系统相册里截图或另存为 JPG
- 已有 PDF 会被渲染成图片再导出，因此**文字不再可选中、可搜索**。要保留原文字层，得用专业的 PDF 页面操作库，属于另一个量级的方案
- 图片或页数过多时，导出会变慢并占用较多内存
